## Package structure

All ROS 2 packages live in `robot-sim/`. Every directory containing a `package.xml` is a package.

### Robot packages

Each robot has one package, generated by [sim create](../../guides/adding-robots/):

**`<robot>/`** — the robot model
- `urdf/<robot>.urdf` — geometry URDF (links, joints, mesh references)
- `meshes/` — STL mesh files from OnShape
- `config/<robot>.rviz` — RViz layout
- Built with `ament_cmake` — installs URDFs, meshes, and configs to the share directory

### Shared packages

**`sim_common/`** — shared Python utilities and the Genesis simulation node
- `genesis_sim.py` — Genesis physics loop, ROS bridge (publishes `/joint_states`, subscribes to `/joint_trajectory_controller/joint_trajectory`)
- `joint_gui.py` — Tkinter GUI for interactive joint control
- `move_joints.py` — one-shot joint trajectory node
- `launch_utils.py` — `get_asset()` helper for launch files
- `launch/sim.launch.py` — shared launch file used by all robots
- Built with `ament_python` (`setup.py`) — registers `genesis_sim`, `joint_gui`, `move_joints` as console script entry points

## Building

The `sim` CLI handles building automatically. To build manually:

```bash title="Terminal"
cd robot-sim
colcon build --packages-up-to arm sim_common \
    --cmake-args -DBUILD_TESTING=OFF
source install/setup.bash
```

`--packages-up-to` resolves and builds all dependencies in the correct order. `source install/setup.bash` makes the built packages visible to ROS 2.

### Build outputs

After building, `robot-sim/` contains three generated directories:

| Directory | Contents |
| --- | --- |
| `build/` | Intermediate CMake/Python build artifacts |
| `install/` | Installed packages — what ROS 2 uses at runtime |
| `log/` | Build and launch logs |

These are all gitignored. Delete them with `sim clean`.

## Adding or modifying packages

When you add or change a package:

1. **`package.xml`** — declare the package name and dependencies (`<depend>`, `<exec_depend>`, etc.). `colcon` uses these to determine build order.
2. **`CMakeLists.txt`** (CMake packages) — add `install()` directives for any new files.
3. **`setup.py`** (Python packages) — add new modules and console script entry points.

:::tip
If colcon can't find a package, make sure `package.xml` exists and the directory name matches the `<name>` tag inside it.
:::

## Troubleshooting

**Unexplained build errors:** Run `sim clean` and rebuild.

**Package not found at runtime:** Source the workspace — `source install/setup.bash`. New terminals don't source it automatically outside the conda env.

**Dependency order issues:** Check that all `<depend>` tags in `package.xml` are correct. Missing dependencies cause packages to build before their dependencies are ready.
