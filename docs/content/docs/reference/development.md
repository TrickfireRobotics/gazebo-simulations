This guide is for modifying the simulation code - tweaking launch files, changing controller config, adding shared utilities, or debugging a broken build.

All development happens inside the Dev Container. See [Docker Dev Container](../../simulate/docker/) if you haven't set that up.

## Package structure

`robot-sim/` is a ROS 2 workspace:

```
robot-sim/
├── arm_description/    # Robot URDF + meshes (generated by genbot, don't edit)
├── arm_bringup/        # Launch files, controller YAML, RViz config (edit freely)
├── sim_common/         # Shared: launch_utils, move_joints, joint_gui
├── sim_worlds/         # Gazebo world files
├── build/              # Build artifacts (gitignored)
├── install/            # Install artifacts (gitignored)
└── log/                # Build logs (gitignored)
```

Each robot has two packages:
- **`<robot>_description`** - URDF + meshes, regenerated by `genbot update`. Don't edit manually or your changes will be overwritten.
- **`<robot>_bringup`** - launch files, controller YAML, RViz config. This is where customizations live. `genbot update` won't touch it.

## Building

Build inside the Dev Container. The standard command builds a robot and everything it depends on:

```bash title="Inside devcontainer"
cd robot-sim
colcon build --packages-up-to arm_bringup
source install/setup.bash
```

`--packages-up-to` resolves the full dependency chain - for `arm_bringup` that includes `arm_description`, `sim_common`, and `sim_worlds`.

To rebuild a single package faster when iterating on one thing:

```bash title="Inside devcontainer"
cd robot-sim
colcon build --packages-select sim_common
source install/setup.bash
```

:::note
You must `source install/setup.bash` after every build before running any `ros2` commands. `launch_sim.sh` does this automatically; manual commands need it.
:::

## Edit → build → run cycle

1. Edit files in `robot-sim/<package>/`
2. Rebuild: `colcon build --packages-select <package>`
3. Source: `source install/setup.bash`
4. Run: `./scripts/launch_sim.sh <robot> --no-build` (skip rebuild since you just did it)

For **launch file or YAML** changes, you can often skip the rebuild entirely - just re-run `launch_sim.sh`. For **Python or C++** source changes, always rebuild first.

## Cleaning stale artifacts

If a build fails for no obvious reason, stale artifacts are usually the cause:

```bash title="Inside devcontainer"
./scripts/ros_clean.sh
```

Deletes `build/`, `install/`, and `log/` from `robot-sim/`. The next build is a full clean rebuild. This also runs automatically when the Dev Container opens.

## Inspecting the running simulation

```bash title="Inside devcontainer"
# All active topics
ros2 topic list

# Joint states in real time
ros2 topic echo /joint_states

# Active controllers
ros2 control list_controllers

# Available hardware interfaces
ros2 control list_hardware_interfaces
```

## Customizing a robot's launch file

`robot-sim/<robot>_bringup/launch/<robot>.launch.py` is the entry point for each robot's simulation. Common changes:

- Add `rviz:=false` or `gui:=false` to disable RViz or the Joint GUI
- Add extra nodes to the launch sequence
- Change the world file

See [Launch System](../../reference/launch-system/) for a full breakdown of the launch sequence.
